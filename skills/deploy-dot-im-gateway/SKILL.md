---
name: deploy-dot-im-gateway
description: Deploy, diagnose, back up, upgrade, roll back or remove the standalone dot-im-gateway service on one Linux host. Uses an existing OpenAI dot through a private official MCP tunnel. Does not create an agent or silently enroll messaging accounts.
---

Use the repository containing this skill. Read [the deployment runbook](../../docs/DEPLOYMENT.md) and [acceptance checklist](../../docs/ACCEPTANCE.md). Run deterministic `scripts/deploy.py` from that repository; it defaults to a plan and performs no downloads. The gateway and official tunnel-client are separate services.

1. Inspect target OS, Node version, current services, port 8788, configured paths, and existing installation marker. Do not modify another repository or replace an occupied service. Back up a stopped instance before upgrade. Keep all state under its explicitly selected prefix.
2. Run `node scripts/release-check.js`, then `python3 scripts/deploy.py install --prefix <path>` to review the exact plan. Apply only when deployment to that target is authorized. Initial config stays offline; no service start or network enrollment occurs during install.
3. **Interactive gate: QR and platform enrollment.** Ask the user to perform the official QQ or Weixin QR flow only after the target account, stable owner ID, application/bot ID, and retained-credential scope are clear. Do not scan, click consent, or obtain credentials automatically. QQ's optional QR helper has an independent UNLICENSED boundary; do not install or redistribute it based on the bridge's MIT license. Prefer already provisioned official credentials. No QR client is bundled here.
4. **Interactive gate: long-lived credentials.** The user enters existing approved secrets locally in the private runtime environment file. Never put secret values in chat, command arguments, source, logs or this Skill. Explain their persistence and how to revoke them. Validate stable IDs, never nicknames. Do not rebind an existing state directory to a different owner.
5. **Interactive gate: private Tunnel and original dot.** Follow current official OpenAI tunnel-client onboarding and CLI help. Inspect/reuse the intended tunnel, org/workspace association and original dot. Before creating a tunnel, key or plugin, obtain the needed explicit authorization. Do not create a replacement dot, model API client or synthetic internal API. Verify the local authenticated MCP call first and configure the tunnel to pass the gateway bearer credential using the official supported mechanism.
6. **Interactive gate: real subscription.** Show the exact platform filter and response behavior to the user. Only then enable `allowSubscriptions`, set exact callback host allowlist from the authenticated product flow, and ask the original dot to subscribe. The dot sends an ack and final using each message's original ID. A successful signed webhook receipt is not a completed dot task or an IM delivery receipt.
7. Run the acceptance checklist with the user. Report separate evidence for offline tests, tunnel tool calls, event verification, original dot task execution, and human receipt. Stop any action whose required authorization is absent; continue independent local checks. Do not call the deployment complete before real owner send/receive acceptance.

For `uncertain` sends, inspect platform evidence with the user; use `reconcile --decision accepted|cancelled` on the stopped service. Never requeue uncertain sends automatically. Restore creates a new directory, revokes subscriptions and quarantines pending replies. Uninstall retains private data and credentials; never purge them as a side effect.
